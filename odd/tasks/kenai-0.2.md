# kenai-0.2
Kenai 0.2: Kenai and Koda as two independent applications that can connect to share chats, automations and mini-Kodas. Base: `release/0.1` at `9d25455`. Kenai 0.1 is not published yet; nothing here ships in it.
The vision is large and not yet cut into slices: the first slice is decided with the human (T1).

## Specs
- S1: Two applications, each working on its own: Kenai on the phone, Koda on the computer. They can connect to each other, for example to share chat information, automations and mini-Kodas, «pero cada uno trabaja a su forma y a su manera». Neither depends on the other. (Replaces the first reading of «2a», chat shared only through the link. It also answers the open question: the phone chats on its own.)
- S2: Other apps (Tasker, Automate, Samsung Routines) can react to Kenai and trigger it through Android intents and broadcasts («3a»). Kept; it is the smallest piece of phone-side automation.
- S3: The user automates from the computer and from the phone. The example Koda already has, the Telegram channel check about «mis acciones», must also be something the user can set up with Kenai: «Y también Kenai me lo tiene que permitir». (Replaces the first reading of «3c», scheduled tasks run only by Koda.)
- S4: Decided («2a», correcting an earlier «2b»). An automation never allows a permission request by itself: Allow always asks for the fingerprint or the screen lock, as in 0.1. An Android intent from another app can never carry an allow either.
- S5: Decided («1a»). Kenai uses the internet on its own for its chat and automations (AI providers, Telegram) and keeps its secrets, the provider keys and the Telegram bot token, in the Android Keystore. Replaces «LAN only, no relay». Proposed, to confirm: what Kenai sends out is limited to what the user configured, and to the provider or channel he configured.
- S8: Decided. The chat providers are the local model through LiteLLM, plus Claude, GPT and «nan builders» (not yet identified: see L10). Several providers from the start, not one.
- S9: Decided. The Mini-Koda engine already exists in Koda, so Kenai uses it as the backend: all the flows run on the machine at the human's home, and Kenai drives them through the link. Kenai does not get its own Mini-Koda engine. (Recommendation 2 of the plan, accepted.)
- S10: Decided. Kenai and Koda must be downloadable and installable by other users on their own machines, «si lo desean». Consequences for the design: nothing hard-coded to the human's machine (no LiteLLM address, no Tailscale name, no key); every endpoint is a setting; the app works on its own without Koda; a release APK on GitHub with install instructions.
- S11: Decided. No hurry for 0.1: the Kenai 0.2 work can start now, in parallel with the 0.1 test on the real phone.
- S6: A central system, «un Jarvis de lo que sería Eineman»: the user sends things to it and it answers «en un lenguaje natural y neutral».
- S7: Mini-Kodas: specialised AI agents for specific processes. «Si un proceso no requiere una IA, pues que tenga su Chrome Job con sus scripts». A process that needs no AI is a cron job with its own scripts.

- L14: Map of Koda's provider design (read-only explorer, no secret read). Koda has two layers; the chat uses the engine accounts: per-account `models.json` `{providers:{<name>:{baseUrl, api, models}}}` with the API styles `openai-completions`, `anthropic-messages` and `google-generative-ai`, and cloud presets Claude, OpenAI, Google, OpenRouter, NaN (`https://api.nan.builders/v1`, `nan-default`, openai-completions) and OpenCode Go.
